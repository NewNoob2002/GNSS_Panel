# P4 原应用源码来源

- 原 View/资源/工具来源：`HC32F460xE_Arduino/Simulator/App`，提交 `37b069a0e76061dbac07e9345e653d1796945bac`；保留许可说明。PageManager 后续已加固路由、卸载和边界，不再是仅头文件适配。
- 本分支移植 `FASTSHIFT/X-TRACK/Software/X-Track/USER/App/Utils/DataCenter`（MIT），源提交 `c42b8e5605e50838f4c0c9828385948fa33ab485`。适配 LVGL include、Account 注册有效性/容量/序号、发布时订阅者删除、多个订阅者销毁清理、参数/分配边界与公共日志；未引入 X-TRACK HAL。
- 每个路由页在自身目录拥有 Controller、View、Model。Model 独占 Account 并订阅/拉取/接收数据、通知服务和 StatusBar；构造函数不注入 DataProc，已删除共享 PageModel。`Common/DataProc` 仅初始化处理 Accounts 并提供 `DataProc::Center()`；路由在 Utils/DataCenter，行为在处理模块/SystemService。
- `P4App` 组合十页、StatusBar 与通用输入。原 Shutdown 路由更名为 SystemDash，不保留旧路由别名；新增 SystemSettings。SystemDash/SystemInfos/SystemSettings 通过各自 Model 通知将状态栏移至屏外，SystemDash 及其 Settings 子页统一使用全屏；StatusBar 仅在工作页等明确需要的页面显示。沿用 HC32 的 500ms y=−26↔0 动画（显示 ease-out、隐藏 overshoot），不切换根对象 hidden flag；反向从当前位置继续，同向不重启。只有页面展示请求控制移动，数据刷新不擅自改变位置。
- RK3506J 真正产品输入是两路 GPIO HIGH/LOW 电平，不是键盘 F/P 或 evdev/ADC 按键；Function/Power 只是逻辑职责名。Function GPIO 单击 NEXT/+1、双击 BACK/CANCEL；Power GPIO 单击 ENTER/选择、双击 COMMIT。主机 SDL 与 UI 测试不使用该绑定或双击等待：方向键/滚轮换焦点，Enter/中键按下与松开（Startup 长按 2 秒启动，其余页面短按选择），Esc/右键返回，Ctrl+Enter 提交，左键指针交互和 Q 退出恢复。当前测试板用 V− 代替 Function、V+ 代替 Power，按下/松开经 on_key()/poll_keys() 复用两键逻辑；V− 单击切焦点、双击返回，V+ 单击选择、双击提交，Startup 长按 V+ 约 2 秒启动演示；MENU/ESC 不再参与。旧四键适配仅 KEY_ENTER 能触发 Commit，测试板没有该键，因而无法确认关机/重启。量产 GPIO chip/line、有效 HIGH/LOW、输入/pull 配置与时序尚未验证，不默认映射。平台读取电平后按确认的有效电平归一化 pressed，再在 UI 线程调用 on_key()/poll_keys()；读取失败应取消输入并报错。linux_button_read_keys() 用于当前 evdev 测试适配，不能替代 GPIO 产品接入。p4_screen 每轮主循环读空 evdev 队列（读取函数跳过 EV_SYN 等记录，NONE 表示队列已空），并以 EVIOCSCLOCKID 选定的 CLOCK_MONOTONIC 事件时间戳调用 P4App::on_key_at()：先按旧电平采样到该时刻，再应用新电平，避免慢帧期间排队的按下/松开被合并或丢失；poll_keys() 对早于上次采样的时间按上次处理。界面不添加测试键提示。
- SystemDash 为 Power/Settings/Return 三卡；其 Settings 子页同样保持 StatusBar 隐藏（88px 宽、7px 间隔），Function 单击循环三项、Power 单击选 Return 使用 PageManager::pop() 返回上页，主机 Enter/指针同样有效；StarMap 隐藏根页黄色焦点外框，保留焦点与点击返回能力；电源弹窗默认 Cancel，Shutdown/Reboot 仅产品 Power GPIO 双击（主机直接 Commit）进入 SaveConfig 后调用模拟 SystemService，重复执行被 token 拦截，提前返回取消事务。按用户确认移除手动日期入口与编辑器及页面草稿逻辑；SystemSettings 仅语言内联切换、禁用 Wi-Fi 与可见 Back，Function 单击循环语言/Back、Power 单击选择，不要求 Up/Down；双击 Function 仍可返回。原 RAM 日期服务/校验契约保留但无手动 UI 入口。没有系统时钟写入、持久化或 Linux/设备关机重启命令。
- 新绘 SystemDash Power/Settings/Return 图像在 `Resource/img/img_src_system_dash_power.c` / `img_src_system_dash_settings.c` / `img_src_system_dash_return.c`，分别为原生 40px 菜单图像，Power 另有 24px 弹窗版本；Return 的可编辑源为 `system_dash_return.svg`。采用 8-bit alpha 掩码、主题重着色，合计像素数据 5376 字节。旧 16px 图像保留供其他页使用，不再在 SystemDash 放大。最新英俄截图见 out/ui-pages/SystemDash/three-tile-return-starmap.png；native-icons-settings.png 是原两卡历史截图。
- Startup 的 FW/HW/BAT、SystemInfos 六张卡的数据及 StarMap 星座计数已填合理演示值，页面标 DEMO；数据尚非实际测量。当前静态信息位于各 View 的 create()/apply_language()，上板接入后由 Model 快照替换相应标签更新。板端旧版拼图见 out/deploy-loading/demo-information.png。
- Startup 最新主机样式为 GNSS RTK 标题/DEMO 徽章、FW/HW 两卡、电池图标/电量槽/实际百分比及电压，以及完整 106×94 Start 长按卡。Startup 与 StatusBar 复用 BatteryStyle：非充电按实际电量显示四级颜色，充电以绿色从空到满循环（1.2 秒增长、0.3 秒停留），数字保留实际电量；数据无效时取消动画；Startup 离页停止自身电池动画，StatusBar 在销毁时清理动画。SDL `--random-status [seed]` 每 3 秒生成可复现状态，经现有 UI 线程发布。电源图标、进度环与居中百分比、英俄 Start/Запуск 和 Hold 2s/Удерж. 2 с 形成明确启动入口；复用 PageStyle 与现有字体/图像，保留 26px 延迟状态栏区域和 2 秒长按行为。主机 CTest 9/9、双语字体/文字宽度/布局、SDL 提示文字处指针按下/提前释放检查通过；截图 out/host-startup-style/preview.png，未部署板端。
- 主机 SystemInfos 按最新要求移除初始化标题与五条结果行，仅保留六张原有信息卡，固定 294×126 视口纵向滚动；显式控件数组按 Work/GPS/Wi-Fi/Battery/Storage/System 注册焦点，Next/Down/Function 正向、Previous/Up 反向，两端循环。System 卡保留初始化失败节点数，System 服务仍保存最近一次报告，Loading 日志和非阻塞初始化行为不变。发现实际运行的 out/host-init-info/application/p4_sdl 是导航修复前的旧二进制，本轮原路径重建并重启。主机 CTest 9/9，生产 SDL 事件循环的队列注入检查确认 Down: Work→GPS、Up: GPS→Work 和完整六卡循环；记录及临时 fixture 位于 out/host-info-clean/。本轮未部署板端，旧初始化卡/紧凑行截图为历史。
- 状态由 DemoStatus/StatusService 提供明确标为 DEMO 的自有快照；所有 LVGL、Account、输入、计时器在主线程执行，未来异步生产者需主循环投递。`Utils/Log` 提供运行时级别、可替换 sink、stderr 默认输出与有界格式化；PageManager/DataCenter 使用同一 API，普通投递日志为 DEBUG。
- 本分支按情境切页：Startup/SystemLoading/Dialplate 与 SystemInfos 淡入，设置/菜单水平推进，StarMap/SaveConfig 从下向上进入；Back 反向退出，时长 280–360ms。PageManager 在缓存页重入时复位未动画轴/透明度，坐标 getter 读取与 setter 一致的对齐偏移，避免跨轴返回残留偏移或底对齐 StarMap 跳动；Oswald 支持英俄，Rajdhani 仅用于数字。Startup 在主机 Enter/中键/左键或测试板 V+（Power）长按 2 秒后进入 SystemLoading；短按、指针移出和窗口失焦取消。重复按下不重启计时，跨页松开不触发下一页。产品电源时序保留为未来平台接入点；归一化 Power 的去抖长按仅启动演示 UI，不将单击伪装为开机。两个开机阶段均用现有 PageManager::replace() 替换前页，Dialplate 为工作根页，Back 不再进入 Startup/SystemLoading；模拟 SaveConfig 完成按动作区分：Off 在未切断系统电源时调用 PageManager::reset_root("Pages/Startup")，清空旧历史并重建待机根页；Reboot 回到工作根页 Dialplate。进度和完成计时在 did_appear 后启动，避免主机长帧撞上未结束的切页。
- Startup 默认隐藏 StatusBar，did_appear 后未完成启动长按则 10 秒滑入；短按取消不重置该延迟，离页删除定时器。SystemLoading 一律上滑隐藏状态栏，先展示 Logo 800ms，220ms 淡入带旋转齿轮/圆环的 System Initialization；控制器每 600ms 调用 Model::initialize_step() 推进配置/服务/GNSS/网络/收尾五阶段，单步记录 begin 与 OK/FAILED 的 DEMO 日志，窗口切换也保留日志。默认网络预留节点演示失败：标题/当前进度红色，失败圆点和连接线持续红色，后续节点照常执行；全部成功时 Ready 绿色，有失败时橙色 Started with warnings / ServicesLimited，100% 保留 200ms、Ready 保持 1 秒再淡入 Dialplate。默认使用 img_src_SystemLoading_XYZ.c（仍导出 img_src_startupLogo）；既有 RGK_LOGO_USE/MIDDLE_LOGO_USE 分别选 RGK/Neutral 文件。界面包含阶段标题、辅助文案、8px 进度条、百分比、Step N of 5、五个连接圆点与 GNSS RTK Receiver 页脚；文字/激活点淡入，Ready 颜色和齿轮→勾选过渡 220ms。英俄用 Oswald（Rajdhani 没有 % 字形）。全程标 DEMO，不代表真实硬件初始化或测量；平台接入须有界且保留失败不阻断规则。离页清理计时器/动画，重入清除失败标记。最新拼图见 out/deploy-loading/initialization.png；旧 out/ui-pages/Boot 拼图/GIF 为历史成功演示。
- 主机测试扩为 9 项，含框架日志/生命周期、页面 Model 数据、直接逻辑操作与双语布局；除直接主机操作外，新增归一化 GPIO 逻辑样本回归，检查两键 Settings 循环焦点和 Back、SystemDash 三项循环及 Return 返回/重新进入，保持电源操作未执行，并检查 StarMap 无外框；不访问真实 GPIO、不改变 SDL 输入适配。SDL 构建及 dummy-video 退出已验证；详细命令与截图路径见 [UI 计划](../../docs/UI_PAGES_OPTIMIZATION_PLAN.md)。本分支两键版本已 ARM 构建并部署，主机 9/9 通过；RK3506 上通过临时 FIFO 定时 evdev 事件验证启动长按、取消、模拟 Off/Reboot，随后恢复真实 /dev/input/event0。实际两键手感和最新画面仍需操作者复核，真实 GPIO/电源仍未验收。详见 [P4 板端记录](../../docs/P4_APPLICATION.md)。
- 平台边界（供 HC32 共用本 App）：系统操作经 `Common/SystemBackend.h` 由平台实现，本仓库的模拟实现与 `DemoStatus` 一起位于 `Status/`，编译为 OBJECT 库 `p4_simulation`，`p4_sdl`/`p4_screen`/既有测试链接它；其他平台链接自己的 `system_backend`。`SystemState` 增加 `powered_on`/`shutting_down`/`standby`/`reboot_available`/`power_cause`：Startup 长按结束只发 `RequestPowerOn`，由后端立即确认（模拟）或由平台稍后调用 `SystemService::set_powered_on(true)`；平台关机经 `begin_shutdown(cause)` 推入不可返回的 SaveConfig 并显示原因；`enter_standby()` 回到 Startup。上述导航由 P4App 的 20 ms 定时器在 Account 回调之外执行。用户 Off 在 SaveConfig 结束时提交，之后等待平台的待机报告（模拟后端立即报告，行为不变）；`reboot_available=false` 时电源弹窗只有 Shutdown/Cancel。`SystemState.simulated=false` 时隐藏标记为 DEMO 的徽章。页面 Model 初始化失败调用可由平台覆盖的弱符号 `app_fatal()`（默认 abort）。`P4App::init({.battery_warning = true})` 启用顶层电池过温横幅（65 °C 出现、低于 60 °C 消失，温度来自状态快照）。`p4_platform_test` 用测试后端覆盖平台确认开机、无重启、平台关机/待机与过温横幅；主机 CTest 10/10。
