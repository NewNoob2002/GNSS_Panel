# 页面结构、视觉规则与验证

共享应用源码位于本仓库 `App/` 与 `Frameworks/`（本仓库为唯一来源）。共享框架、核心服务与 UI 的构建边界见 `App/ARCHITECTURE.md`。本文描述当前页面与过渡；3.0.0 的用户变化见[发布说明](release_notes.md)。

## 当前职责与入口

```text
待机 Startup → 初始化 SystemLoading → 首页 Dialplate
                                      ├─ 工作配置 WorkSettings
                                      ├─ 记录管理 RecordConfig
                                      ├─ 设备信息 SystemInfos
                                      ├─ 系统 SystemDash
                                      │    ├─ 亮度（五档）
                                      │    ├─ 语言
                                      │    ├─ Wi-Fi（按产品能力）
                                      │    ├─ 电源 → 确认 → SaveConfig
                                      │    └─ 返回
                                      └─ 卫星区 → 卫星详情 StarMap（按产品能力）
```

| 页面 | 职责与本轮调整 |
| --- | --- |
| Dialplate | 快速查看工作状态并进入常用任务。四个入口以原 Device Info 三横线为视觉基准，统一原创白色 16×16 alpha 图标：工作参数、记录、信息列表、系统齿轮。移除底部焦点文字，按钮恢复 56×32；卫星区保持纯数值。录制中以红框提示，不伪装为直接停止按钮。右侧两张状态卡：电台卡为天线，开启时两侧画收发波形（TX 外扩、RX 内收）；模式卡为 RTK 设备造型（基准站=三脚架接收机，移动站=对中杆接收机加手簿），基准站天线罩上方播发弧依次外扩，移动站信号点落入天线罩后杆尖扩散测点涟漪。动效均画在图标外侧，仅工作模式有效时运行，按 50 ms 步进重绘。 |
| WorkSettings | 选择电台移动站、电台基站、网络基站预设，再调整电台参数并显式应用。预设切换不直接下发命令。网络基站隐藏电台字段。主卡顶部装饰条跟随预设颜色（移动站绿、基站蓝），不与橙色焦点框混淆。 |
| RecordConfig | 显示记录状态、剩余空间、格式/间隔及启停。默认聚焦主操作，开始与停止都是单击（双击同样有效）；记录中和请求等待时锁定参数。XBase 显示固定参数，不再展示禁用的调整箭头。 |
| SystemInfos | 恢复全屏只读诊断，保留工作、定位、网络、电池、存储、系统六项。每次进入默认聚焦根页面，滚轮/方向键翻阅信息项，根页面或信息项点击即返回；不保留上次查看项、不显示新增浏览提示。聚焦卡片收窄为 84 px 标题卡（渐变底 + 橙色焦点框，图标按信息色着色），字段名与数值分两列；温度带 °C，充电状态为可读文案，存储卡在停止时也显示剩余空间（整数 MB）与格式/间隔，文件名仅录制中显示。 |
| SystemDash | 保留状态栏，与工作/记录设置共用网格：左侧 88×77 px 亮度主卡（x=8、y=28），右侧 x=102、宽 186 px 的语言和 Wi-Fi 行（y=28/55、高 23 px），底行 y=82 为红色电源 138 px + 仅图标返回 42 px（x=246）。亮度主卡以橙色大太阳、标题和五段短线表示档位：各 10×4 px、间隔 4 px、整体居中，橙色亮起 1..5 段对应 20%..100%，未亮段为暗橙色；点击循环档位，焦点按亮度→语言→Wi-Fi→电源→返回循环。Wi-Fi 始终显示开关或等待状态，不可控时置灰并跳过焦点，能力异步变化不重排或重建对象。入场先主卡再右侧行依次错峰。旧 SystemSettings 代码与路由已删除，无兼容别名。电源确认窗位于状态栏下方，标题 18 号字；关机红、重启橙，未聚焦文字提亮，聚焦/按住时强化底色与文字，按钮底部 3 px 轨道显示长按进度，不再铺满整块按钮；重启仅按平台能力显示（HC32 不提供）。 |
| StarMap | 各星座数量详情，可见标题为 Satellites/Спутники，内部路由保留。 |
| Startup | 待机信息、电池、完整长按 2 s 后请求平台开机；HC32 带屏产品仅接受此请求（软件复位自动开机除外）。无卡片：左侧大号电量数字、电池条与 FW/HW 一行，充电时 CHG 旁在有效平均电流 ≥ 50 mA 时显示一位小数 W，否则保留两位小数电压；电池无效为 BAT / N/A，右侧透明长按区为进度环与电源图标，下方“开始/长按 2 秒”同一行。 |
| SystemLoading | 品牌和初始化阶段：按平台真实检查结果推进（每步耗时不固定，最短显示 300 ms，超过 1 s 显示等待秒数），失败标红不中断启动，完成时有失败显示警告。HC32 第 5 步等待主控通信最长 30 s。 |
| SaveConfig | 用户关机准备与平台关机原因。进入前的电源确认窗：长按 Power 2 s 进度满 100% 确认，短按或提前松开关闭窗口；平台关机不可取消。无卡片：左侧进度环（关机红、重启橙）内含电源图标与百分比，右侧竖直居中的动作、原因、提示三行文字。 |

页面按任务划分，工作、记录与只读信息继续独立；整合了价值较低的系统设置中间层，工作页焦点从原来 8 个减少为 5 个（网络基站 3 个），记录页从 6 个减少为 4 个（固定参数或记录中仅主操作与返回）。

亮度设置沿 `dp::Settings → Board → HAL::Display_SetBrightness → DCS 0x51` 下发，五档 20/40/60/80/100% 使用 CIE L* 表 0x33/0x53/0x7F/0xB8/0xFF；默认 100%，仅存 RAM，屏幕复位恢复所选值。SDL Board/Demo 共用该表预览；Linux Demo 只保留状态。充电功率的数据来源、有效性与回退见[待机页充电功率](battery_charging_power.md)。

## 工作预设和应用反馈

- 进入工作页时从设备快照读取预设、协议与信道，默认聚焦预设；选择在三种预设之间循环，协议/信道各自单击循环。
- 点击 Apply 才发送，提交动作也仅在聚焦 Apply 时有效。CUSTOM 信道用于电台预设时留页提示，网络基站不受此限制。
- 页面保持打开，反馈区分等待主控、请求已接收、拒绝、15 秒超时；等待期间不允许覆盖同类请求，但始终可以返回。
- 记录操作复用相同的反馈规则。开始与停止都是单击（双击/Commit 同样有效），等待主控确认时按钮锁定，重复提交不会覆盖正在等待的请求。
- 状态栏 SD 图标跟随主控回报的实际录制状态（HC32 `BusinessDevice::recorder()` 读 `systemInfo.host.record`，经 Recorder 领域节点发布）：变化时先滑出状态栏、在栏外换色再滑回，录制中蓝色闪烁，未录制为静止白色；主控确认前不变。
- 返回页面不取消已经发送的主控请求，超时也不清除平台请求；迟到的确认会更新为已接收。
- HC32 `BusinessDevice` 将 `work_pending`、`record_op || record_settings_pending` 映射为 Work/Recorder 领域的等待状态。协议确认的是主控已读走请求，**不是物理操作已经完成**，因此文案使用 Request received，不显示 Apply succeeded。
- 模拟后端可同步接受并发布状态；真实平台可异步报告，页面兼容两种情况。等待定时器在离页及卸载时清理；语言更新不重建其他缓存页的焦点组。

## 视觉与动画

通用颜色集中在 `App/UI/Common/PageStyle.h`。

| 语义 | 颜色 |
| --- | --- |
| 背景 / 面板 / 卡片 | `#101214` / `#202428` / `#181C20` |
| 边线 / 主文字 / 次文字 | `#414A52` / `#F2F4F5` / `#A4ADB5` |
| 焦点边框 / 焦点底色 / 按压底色 | `#FF931E` / `#34302A` / `#3A424A` |
| 正常、移动站、RX / 基准站、TX、连接 | `#28C76F` / `#3498DB` |
| 危险、失败 / 进度高亮 | `#D03C3B` / `#F6D062` |

状态栏定位色同样取自上表：无解/演示为危险红，基准站为信息蓝，单点/浮点为进度黄，固定为正常绿；电池按电量取正常绿（≥50% 或充电）、焦点橙（20–49%）、低电浅红 `#EA5455`（10–19%，`battery::kLow`）、危险红（<10%）。首页状态卡的 ROVER/BASE/OFF 随语言切换，RX/TX 为电台通用缩写不翻译。星座分类色条、Logo、过温横幅继续使用各自的语义色。圆角沿用 8–12 px，焦点橙框由 FocusHighlight 弹簧跟随；按下时橙框向内挤压、松开回弹（控件保留按压底色，不再自绘橙框）。Dialplate 已移除重复的边框颜色过渡，连续 100 次快速正反向切焦点回归检查只有当前控件显示橙框。

工作、记录保留左侧图形主卡和右侧参数/操作卡，系统页采用左侧亮度主卡与右侧三行网格，主卡五段短线显示档位；共用原生 16/32 px 图标，工作、记录另有渐变、网络连接图形与状态点。控件每隔 40 ms 依次从下方 6 px 上移进入（只做位移、不做透明度，避免与页面滑动叠加的逐控件混合开销），数值变化时短淡入；只有主控等待或记录进行时状态点持续呼吸，离页和销毁时停止。正常状态不增加操作说明文字，错误、等待、确认等业务反馈保留。

`Vendor/Linux/tools/generate_ui_icons.py` 保存原创矢量路径并用已有 ImageMagick 生成原生尺寸 alpha 资源（16/32 px 按各自网格单独设计）。渲染先 8 倍超采样再按整数倍盒式平均得到真实像素覆盖率（不用会产生振铃灰边的 Lanczos 缩放），2 单位描边、方头斜接，使横竖线落在整像素上；覆盖率再经过渡带收紧（45° 小块拼成的卫星图标用更窄的过渡带）。自检包含像素数量、亮度、首页图标墨量，以及半透明像素不超过有效像素一半的清晰度检查。未引入外部图标下载依赖，固件运行时不缩放图标；亮度主卡使用独立的 32 px `ui_sun_large`，首页系统入口继续使用齿轮。SystemInfos 的 6 张信息卡图标为单色白图，运行时统一着色，已无损转为 A8（只存透明度，体积为原 RGB565A8 的 1/3）。

状态栏分左右两组按内容紧凑排列：左为卫星图标与卫星数、定位箭头与定位状态，中为时钟，右为 SD、Wi-Fi、电池与电量，数值统一 18 号字，电池槽内宽 20 px。图标全部为生成的 alpha 图片（替代原 `statusbar` 字体符号），由 recolor 着色。充电时电池条从当前电量扫到满（起点最多为槽宽 4/5，满电时仍可见扫动）、停留 0.3 s 后循环，电量变化时从新起点重启。SD 图标跟随平台上报的录制状态：变化时先上移滑出状态栏，在栏外换色，再回弹滑入；录制中蓝色闪烁，未录制为静止白色，快速往返以最后一次上报为准。状态栏、首页与设置页刷新只在值变化时调用 LVGL，空闲时不再周期性重绘。

字体：正文/字段/按钮用 Oswald Bold 12，标题与状态栏数值用 Oswald Bold 18；20 px 以上的醒目数字（首页卫星数、开机电量、关机倒计时）用只含 0–9 的 Rajdhani Bold 20/40，其余数字均用 Oswald。两个 Oswald 字体只收录界面实际用到的字符：ASCII 32–126、°、俄文 А–я 与 Ё/ё，在字体目录下用 `npx lv_font_conv@1.5.3 --bpp 2 --size <12|18> --no-compress --font Oswald-Bold.ttf --range 32-126,176,1025,1040-1103,1105 --format lvgl -o font_oswaldBold_<12|18>.c` 生成（字距为工具默认的字符对格式）。新增界面文字若用到其他字符，需扩大 `--range` 后重新生成（`app_system_dash` 测试会检查其截图页面中的缺字形）。bpp 4 实测只改变约 0.2% 的像素（Oswald 在 12/18 px 经 hinting 后笔画已对齐像素），不值得多占 2–5 KB，保持 bpp 2。裁掉未用字符后，18 号行高由 26 降为 23 px（基线到行顶仍为 20 px，顶部对齐文字不动，多行标题更紧凑）；Startup 电量数字与 % 的基线补偿改为由两种字体的 `base_line` 计算，不再写死。Rajdhani 数字字体用 `--font Rajdhani-Bold.ttf --symbols 0123456789` 以相同参数生成。字体源文件 `Oswald-Bold.ttf`、`Rajdhani-Bold.ttf` 来自 Google Fonts（SIL OFL 1.1，许可证见同目录 `*-OFL.txt`）。

| 页面 | 过渡 |
| --- | --- |
| Startup | 无页面滑动，开机首屏亮度渐亮 |
| SystemLoading | `FADE_THROUGH` 300 ms，`style::panel_transition_path`：全屏黑色遮罩渐浓，加载页根保持隐藏；结束时显示黑底加载页、删除遮罩，再启动 Logo 背景淡入与逐字浮现（1300 ms），之后开始自检 |
| Dialplate | 从底部覆盖上推（下方加载页同时压暗）；首页面板与按钮稍晚同向升起（仅开机首次进入播放，返回首页不重播） |
| WorkSettings / RecordConfig / SystemInfos / SystemDash / StarMap | 从首页入口进入时：焦点框从入口展开为页面背景色面板（缓入缓出 `cubic-bezier(0.4, 0, 0.2, 1)`，橙框随之淡出），约 350 ms 盖满屏幕即以 `PageManager::pushWithAnim(..., NONE)` 直接切换，新页控件依次浮现；返回同样直接切换，首页保留不透明面板，待子页卸载、切换结束后的首帧刷新完成即用完整 350 ms 收回到原入口，填充淡出、橙框淡入（无固定满屏等待）（参照 smooth_ui_toolkit SmoothSelectorMenu 的 open）。展开动画时长取 500 ms 并在盖满时即完成，使切换发生时面板仍在中速移动，不出现曲线末段近乎静止的满屏等待。未经过首页入口展开的导航使用页面自身的视差推入 `PUSH_LEFT`：新页完整滑入，旧页只左移 1/3 并逐渐压暗，Back 反向。SystemDash 电源面板淡入 |
| SaveConfig | 从底部覆盖进入 `OVER_TOP`，下方页面同时压暗 |

常规页面切换使用 `style::kPageTransitionMs`（350 ms）、`cubic-bezier(0.2, 0, 0, 1)` 曲线（`style::page_transition_path`），Back 沿同一过渡反向退出。SystemLoading 的纯色过渡单独使用 300 ms、`cubic-bezier(0.4, 0, 0.2, 1)`；`FADE_THROUGH` 进入与返回都将单色遮罩从透明渐至不透明，再显示进入页。Logo 播放和完成计时均在 `onViewDidAppear` 启动，保留完整 1300 ms 展示窗口及原自检/完成时序。

遮罩（`PageManager::setScrimOpa`，应用取 `style::kPageScrimOpa` ≈ 45%）在 `OVER_*`、`PUSH_*` 切屏时临时创建于被覆盖页与覆盖页之间，只铺在覆盖页尚未盖住的条带上，切换结束即删除；它按与页面动画相同的进度自行计算覆盖页位置（LVGL 新动画插在链表头部、先于页面动画执行，读实际坐标会落后一帧）。主机基准 `app_transition_bench`（首页往返三个子页，Release，同机相对值）：`MOVE_LEFT` 89.9 µs/帧，`PUSH_LEFT` 无遮罩 101 µs/帧（被覆盖页在新页下的重绘 +12%），加遮罩 117 µs/帧（混合再 +16%）。入口展开（SystemInfos 往返）59.7 µs/帧、刷新 23.3 屏，同一页视差推入加遮罩为 110.5 µs/帧、45.1 屏，即入口展开约为后者的一半。`LV_DRAW_SW_CIRCLE_CACHE_SIZE` 4→8 实测无可测差异，保持 4。实机帧率用调试固件的 `LV_USE_PERF_MONITOR` 确认；若 MCU 上切屏掉帧，可把 `kPageScrimOpa` 设为 0（省遮罩）或改回 `MOVE_LEFT`（省视差重绘）。

开机纯色过渡基准（`app_transition_bench 30`，Linux 主机 Release，294×126 RGB565、42 行部分缓冲，19 帧覆盖 300 ms，统计 `lv_timer_handler` 含渲染的每轮均值之中位数）：Startup 整屏静态重绘 48.8 µs/帧，`FADE_THROUGH` 65.7 µs/帧，同次 SystemInfos 视差推入加遮罩 110.9 µs/帧。纯色过渡约为该推入方案的 59%，约为本次静态整屏重绘的 1.35 倍；静态基线主动失效整屏，与零脏区空闲帧或此前约 30 µs 的基线口径不同。这些数值不代表 HC32 实机耗时。

为在性能不足时保持流畅：

- **不用整页淡入**：开机改用 `FADE_THROUGH`，复用全屏单色遮罩压暗离开页，进入页隐藏至切换结束；根对象不平移、不做整页透明度混合，也不需要离屏图层。遮罩默认黑色，`PageManager::setFadeThroughColor` 可指定颜色，`setScrimOpa(0)` 不会关闭纯色过渡。整页透明度需要按块渲染到带透明通道的图层再逐像素混合，是 MCU 上最贵的切换；且升级前的 LVGL 8.3 对含全屏子对象的页面（SaveConfig 的背景层）在该图层中绘制错位，表现为切到关机页时一闪花屏（主机逐帧渲染复现，改为滑动后消失）。
- **创建与返回首帧耗时不计入动画**：被弹出的页面会卸载，每次进入都要重新创建；`PageManager::switchTo()` 先建页、再 `lv_anim_refr_now()`、最后启动切换动画（回归模拟 200 ms 创建）。LVGL v9.6 为每个动画保存启动时基，但启动后的卸载和首帧渲染仍会消耗动画时长；Dialplate 在 `onViewDidAppear()` 注册一次刷新完成通知，切换结束且首帧刷新完成后立即启动收回，离页/卸载取消通知，避免首帧已经跳到曲线中段。面板在展开完成后的静默尾段保持不透明，返回不闪出首页；慢卸载/首帧各 200 ms 的回归逐帧检查几何、填充/边框透明度、首帧 step 0 与可见 350 ms，换焦点仍可中断。
- **预加载**：SystemLoading 期间（常在等主控）预先创建首页和关机页 SaveConfig；其余页面进入时创建——96 KB LVGL 池放不下所有页面常驻，全量预加载在主机测试中耗尽内存池。
- **减少叠加动画**：控件入场与首页入场只用位移；首页入场不再改坐标/高度（不触发重新布局）；屏幕对象关闭滚动条，滑动时不再画溢出滚动条。
- **SystemDash → SaveConfig**：长按完成时确认窗保持原样，切换结束（`did_disappear`）后再关闭，下层画面在滑动中不变化。

## 卫星数字布局

两组数字与斜杠按字体基线对齐，使用 LVGL flex 按实际位数紧凑居中，两侧保持 2 px 间隔。三位 NumberFlow 隐藏前导零但不留空位，消除原先 `% 100` 的回绕。有效 0 显示 0，无效数据为 `-- / --`。回归覆盖个位、两位、三位及混合组合，检查数字位、间距、居中、基线和容器边界。

## 剩余边界

- 未上板检查 AMOLED 帧率、屏幕遮挡和真实两键手感，也未改变主控协议。
- SaveConfig 仍使用既有固定准备时间，不能作为后端真实保存进度；本轮不改电源业务时序。
- 重新进入工作页/记录页时，等待中请求的 15 s 超时从进入时刻重新计算，只影响超时提示出现的时间。
- `App/` 与 `Frameworks/` 以本仓库为唯一来源；生成资源沿用各自文件行尾，避免无关重格式化。
